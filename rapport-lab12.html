Rapport de réalisation : l'application mobile quitte Expo Go. 01 D'Expo Go à une application compilée

Expo Go exécute le JavaScript que lui envoie le serveur de développement d'un ordinateur : l'ordinateur éteint, l'application disparaît. Un APK contient tout — le moteur React Native, les modules natifs et le JavaScript assemblé une fois pour toutes — et porte son propre nom et son propre identifiant. EAS Build fait la compilation Android (Gradle) sur les serveurs d'Expo : aucune installation d'Android Studio n'a été nécessaire.

04 Les variables d'environnement EAS

Le piège du Lab 11 se rejoue : apps/mobile/.env est ignoré par Git, donc absent de ce qu'EAS envoie. Avant la déclaration, eas config l'annonçait déjà : « No environment variables … found for the "preview" environment ». Les deux variables ont été envoyées depuis le .env par eas env:push preview --path .env, lancée par l'utilisateur : leurs valeurs ne sont jamais passées par l'outil.

Et l'APK final les contient bien (section 08) — comme VITE_ sur le web, une variable EXPO_PUBLIC_ est lisible par quiconque extrait l'APK : sans danger pour la clé publique protégée par la RLS, et c'est pourquoi service_role n'y figure pas.

05 Une session qui survit à la fermeture

React Native n'a pas de localStorage : sans stockage fourni, supabase-js garde la session en mémoire, et l'utilisateur est déconnecté à chaque fermeture — la limite relevée au Lab 10. Le package partagé accepte maintenant un troisième paramètre, optionnel :

packages/shared/src/supabaseClient.ts

export function initSupabase(
  url: string,
  anonKey: string,
  options?: SupabaseClientOptions<"public">
): SupabaseClient {
  if (!client) {
    client = createClient(url, anonKey, options);
  }
  return client;
}

Le web n'a pas changé : initSupabase( import.meta.env.VITE_SUPABASE_URL, import.meta.env.VITE_SUPABASE_ANON_KEY );. Seul le mobile passe un stockage :

apps/mobile/app/_layout.js

initSupabase(
  process.env.EXPO_PUBLIC_SUPABASE_URL,
  process.env.EXPO_PUBLIC_SUPABASE_ANON_KEY,
  {
    auth: {
      storage: AsyncStorage,
      persistSession: true,
      autoRefreshToken: true,
      // Pas de session a lire dans une URL de page, contrairement au web.
      detectSessionInUrl: false,
    },
  }
);

La preuve, sans téléphone. Node n'a pas de localStorage non plus. apps/mobile/test-session-lab12.mjs regroupe le vrai package partagé et le fait tourner dans deux processus séparés : le premier se connecte, le second — tout neuf, comme une application rouverte — relit la session. Le stockage de test reprend les trois méthodes asynchrones d'AsyncStorage, écrites sur disque.

10 Bonus : mettre à jour sans recompiler

expo-updates a été installé avant l'unique build : l'APK interroge ainsi u.expo.dev à l'ouverture et télécharge le JavaScript publié sur son channel, pour la même runtimeVersion (1.0.0). Une correction de texte — le sous-titre de l'écran Profil, qui donne désormais l'adresse du site — a été fusionnée (PR #11) puis publiée :

eas update --channel preview --environment preview --platform android \
  --message "corrige le sous-titre du profil : adresse du site"

--platform android s'ajoute à la commande du sujet : eas update:configure n'a défini la runtimeVersion que pour Android, la seule plateforme construite ici.

Messagecorrige le sous-titre du profil : adresse du site

Il faut fermer et rouvrir l'application deux fois : la première ouverture télécharge la mise à jour, la seconde l'applique. Limite à connaître : seul le JavaScript se met à jour ainsi ; un nouveau paquet natif, comme AsyncStorage, exige un nouveau build.

13 Ce qui reste à faire par l'équipe

Installer l'APK sur un téléphone Android depuis le lien du README, puis mener les dix points de la recette en 4G, Wi-Fi coupé. Les lignes 4 (session après fermeture) et 10 (deuxième téléphone) ne se vérifient que sur un appareil réel.

Vérifier la mise à jour EAS Update : sur l'écran Profil déconnecté, le sous-titre doit devenir « Le meme compte que sur senevent-mbow.vercel.app. » après deux ouvertures.

L'iPhone reste hors périmètre : installer hors App Store demande un compte Apple Developer payant. Les membres équipés d'un iPhone continuent avec Expo Go — qui demandera, pour le SDK 57, un Xcode ≥ 26.4 sur la machine pour les builds iOS locaux.

Et maintenant : la soutenance

Les deux clients sont en production : le site sur senevent-mbow.vercel.app, l'application Android à installer depuis expo.dev. La démonstration croisée — créer un événement sur le web, le voir et s'y inscrire sur le téléphone, et inversement — se fait désormais sans aucun ordinateur de développement. Une logique métier écrite une fois au Lab 7, deux interfaces, une base.
