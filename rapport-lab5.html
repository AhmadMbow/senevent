01 Le schéma SQL

Trois tables applicatives sous le schéma public, greffées sur la table auth.users fournie par Supabase. Clés primaires, clés étrangères, contraintes check et valeurs par défaut sont déclarées en base — la structure ne peut pas être contournée depuis le client.

supabase/migrations/001_schema.sql

create table public.profiles (
  id uuid primary key references auth.users (id) on delete cascade,
  nom text not null,
  telephone text,
  role text not null default 'PUBLIC'
    check (role in ('PUBLIC', 'ORGANISATEUR', 'ADMIN')),
  created_at timestamptz not null default now()
);

create table public.evenements (
  id bigint generated always as identity primary key,
  titre text not null check (char_length(titre) >= 3),
  categorie text not null check (categorie in
    ('concert','expo','conference','atelier','soutenance')),
  lieu_nom text not null,
  date_debut timestamptz not null,
  prix integer not null default 0 check (prix >= 0),
  image_url text,
  organisateur_id uuid references public.profiles (id) on delete set null,
  created_at timestamptz not null default now()
);

create table public.inscriptions (
  id bigint generated always as identity primary key,
  evenement_id bigint not null references public.evenements (id) on delete cascade,
  utilisateur_id uuid not null references auth.users (id) on delete cascade,
  created_at timestamptz not null default now(),
  unique (evenement_id, utilisateur_id)
);

02 Row Level Security

Dès qu'on active RLS, l'accès est refusé par défaut (deny-by-default) tant qu'aucune politique n'autorise l'action. On écrit alors une politique par cas d'usage. Distinction clé : using(...) filtre les lignes existantes visibles/modifiables ; with check(...) contraint les valeurs d'une ligne insérée ou modifiée.

supabase/migrations/002_rls.sql — exemple table evenements

alter table public.evenements enable row level security;

-- Lecture publique (meme anonyme)
create policy "evenements_select_public"
  on public.evenements for select using (true);

-- Insertion pour un utilisateur authentifie, qui devient organisateur
create policy "evenements_insert_auth"
  on public.evenements for insert to authenticated
  with check (organisateur_id = auth.uid());

-- Modification / suppression par le proprietaire seulement
create policy "evenements_update_owner"
  on public.evenements for update to authenticated
  using (organisateur_id = auth.uid());

Les tables profiles et inscriptions suivent le même modèle : lecture publique, écriture restreinte au propriétaire via id = auth.uid() ou utilisateur_id = auth.uid(). La contrainte unique(evenement_id, utilisateur_id) interdit la double inscription au niveau de la base.

03 Le client Supabase dans React

Le SDK est instancié une seule fois depuis les variables d'environnement de Vite (préfixe VITE_), exposées via import.meta.env. Le fichier .env.local reste hors de Git (.gitignore) : la clé n'apparaît jamais dans l'historique.

src/lib/supabase.js

import { createClient } from "@supabase/supabase-js";

const url = import.meta.env.VITE_SUPABASE_URL;
const anonKey = import.meta.env.VITE_SUPABASE_ANON_KEY;

if (!url || !anonKey) {
  throw new Error("Variables Supabase manquantes. Verifiez .env.local");
}

export const supabase = createClient(url, anonKey);

App.jsx — écoute de session

useEffect(() => {
  // Session actuelle au montage (lue depuis le localStorage)
  supabase.auth.getSession().then(({ data }) => setSession(data.session));

  // Ecouter login / logout / refresh de token
  const { data: subscription } = supabase.auth.onAuthStateChange(
    (_event, newSession) => setSession(newSession)
  );

  return () => subscription.subscription.unsubscribe();
}, []);

getSession() lit la session en cache au montage ; onAuthStateChange maintient l'état session synchronisé à chaque login, logout ou rafraîchissement de token. La fonction de nettoyage désabonne l'écouteur au démontage.
